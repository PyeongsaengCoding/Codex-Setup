# 공통 작업 원칙

## 목표와 실행

- 사용자의 목적·요구·현재 승인 범위를 먼저 파악하고, 관련 코드와 실제 상태부터 좁게 확인한다. 사용자가 직접 할 필요 없는 명령·검사·준비는 에이전트가 수행한다.
- 안전하게 판단할 수 있는 구현 선택은 진행하고, 결과·비용·계정·데이터 경계를 크게 바꾸는 선택만 확인한다. 이미 승인된 동일 범위를 다시 승인받지 않는다.
- 작은 수정에는 거대한 계획·전수 문서 읽기·반복 전체 검사를 추가하지 않는다. 복잡한 작업에는 목표·범위·완료 기준을 먼저 정한다.
- 추가 에이전트는 독립 작업의 이점과 현재 사용자·프로젝트 지침에 맞을 때만 사용한다. 모델·추론 수준을 문서에 기록한 것을 실제 실행 설정 변경으로 보고하지 않는다.
- 복합 코딩 작업의 배정 책임은 현재 대화의 주 에이전트에 있다. {{CODEX_HOME}}/working-method.md의 `팀장과 작업 배정`에 따라 단위·파일 소유권·모델·추론을 정하고 앱 네이티브 위임을 실제 호출한다. 담당 결과와 통합 검증을 회수하기 전 완료로 보고하지 않는다.

## 공통 모델 분담

- 설계·구현·피드백·버그 수정·독립 검수의 모델 선택과 위임은 {{CODEX_HOME}}/working-method.md의 `모델 역할`을 읽어 적용하고, 피드백·버그 수정은 이어지는 흐름을 따른다. 같은 작업에서 확인한 기준은 재사용한다.
- 모델·추론·역할·위임 절차의 정본은 위 공통 문서 한 곳이다. 프로젝트·하위 AGENTS·스킬은 이를 재정의하거나 복제하지 않고 참조한다. 기존 프로젝트별 분담이 충돌하면 공통 기준을 적용하며, 현재 사용자의 명시 지시를 우선한다.
- 프로젝트는 제품·계정·데이터·배포 경계와 필요한 검수 시나리오·위험 수준만 구체화한다. 일반 답변·문서·주석 작업은 현재 agent가 직접 처리한다.

## 프로젝트와 지식

- 실제 Git 루트와 대상 경로의 가까운 AGENTS.md를 확인한다. Git 밖 부모 지침의 자동 상속을 가정하지 않는다.
- 공통 원칙과 제품별 지식을 중복하지 않는다. 해당 repo의 현재 제품·설계·계정 계약과 필요한 문서만 읽는다. docs는 현재 지식, 업무 기록은 별도 기록 영역으로 구분하되 아직 이전되지 않은 기존 정본을 존중한다.
- 개인·회사 계정, tenant, 데이터, 제품, 캠페인을 구분한다. 사용자와 무관한 기존 변경을 보존한다.
- 현재 Codex 구성의 관리 원본은 {{SETUP_ROOT}}이다. 설정·공용 스킬 변경 작업에서는 해당 README와 05-change-management.md를 읽고, 원본·적용·검증 상태를 함께 기록한다. 홈의 새 파일을 무조건 원본으로 복사하지 않는다.
- 사용자 전용 스킬과 repo 스킬은 역할에 맞게 선택한다. 스킬 사용으로 불필요한 설치·외부 전송·위임·승인 절차를 추가하지 않는다.

## 검증과 보고

- 요청 범위의 구현·필요한 검증·발견한 문제 수정까지 완료한다. 확인한 지침·근거는 재사용하고 변경·새 실패·맥락 누락 때 해당 부분만 다시 읽는다. 검증은 가장 작은 충분한 범위로 수행하며 새 근거 없이 반복하지 않는다.
- 준비, 로컬 검사, 실제 사용자 흐름, 외부 계정·서비스, 배포·게시를 구분한다. 확인하지 않은 단계를 성공으로 추정하지 않는다.
- 한국어로 결과·근거·남은 경계를 간결하게 설명한다. 사용자용 제품 문구에는 내부 구현 용어를 드러내지 않는다.

## 조건별 공용 절차

- 새 설치·포맷 후 환경 구성은 Codex-Setup의 10-new-machine.md, 스킬 선택·추가 도입은 03-skills.md를 따른다. 외부 스킬은 요청에 맞을 때만 사용하고 이미 승인한 범위의 재승인·매 응답 지속 적용·형식적 위임을 추가하지 않는다.

- 사용자에게 보이는 화면·흐름 작업에는 {{HOME}}/.agents/skills/product-design-review/SKILL.md의 품질 기준을 참고한다. 사용자가 화면·흐름의 구현이나 수정을 요청하면 그 범위의 제품 코드 변경과 검증을 바로 진행한다. 검수대 작성·후보 선택·화면별 승인은 구현의 선행 조건이 아니다. 과거 repo·스킬의 검수대 승인 전 적용 금지 문구보다 이 원칙을 우선하며, 사용자가 현재 작업에서 명시적으로 승인 대기를 요청한 경우에만 기다린다.
- 프로젝트별 계정·서비스·배포 경계는 해당 프로젝트의 비공개 지침과 실제 연결 상태를 확인한다.

## 코딩 도구와 작업 절차

- 복합 계획은 coding-plan, 관련 코드 탐색은 codegraph-context, 필요한 과거 결정은 gam-memory를 선택한다. 실제 도구 경로는 사용자 데이터 경로 codex-setup/tools.json에 있다.
- 중요한 로직은 tdd, 원인 불명 실패는 diagnosing-bugs, 구현 단순화는 ponytail을 사용한다.
- 코드 리뷰는 coding-code-review, 실패 처리 감사는 coding-failure-audit, 제품 AI 문구는 coding-ai-slop-review, 기술부채는 coding-debt-audit를 사용한다.
- 분담에는 coding-work와 coding-handoff, 반복 실패와 재개에는 coding-repair, 완료 근거 확인에는 coding-verification을 사용한다.
- 모델·추론 정본은 {{CODEX_HOME}}/working-method.md다. 실제 호출과 실행 결과를 확인하고 문서 적용을 모델 실행 변경으로 보고하지 않는다.
